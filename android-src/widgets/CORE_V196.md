# Native actions in v196

Version code 196 / version name 1.9.86 retains the five providers, their identities, calendar geometry, original startup GIF, package name and signing certificate from v195.

CalendarSplit and CalendarFortnight show add controls beside TODO and MEMO. All four calendar day dialogs also offer these additions. `WidgetNoteActivityV196` is a private native dialog with no MainActivity launch. It validates a title up to 180 characters and an optional TODO date, preserves the form through rotation, and saves an owner-bound local draft. A memo uses the existing `add-memo` transaction and the notebook's `checklists` memo collection. Native projections show the new entry immediately and distinguish pending or failed synchronization.

RoutineAll's row and **완료** button toggle today's MAX completion. MINI, MORE and SKIP remain available. `WidgetActionReceiverV196` receives these explicit actions without starting an Activity; the fixed weekly statistics panel still opens the existing app statistics tab directly. A stale gesture across midnight deliberately uses the current device day after looking up the current owner and record. Previously queued commands retain their original dates. The current overlay decides a repeated completion tap, so an immediate second tap removes completion without creating duplicate dates. Goal-linked routines show a useful explanation and reject direct mutation, matching the existing cloud transaction's guard.

`WidgetPrivateV196` stores at most 100 active commands per owner. Only an unclaimed routine/date or TODO action can be replaced by a newer gesture, with a new key. `privatePendingV196` atomically claims one command before returning it. Its date, value, expected revision and key then remain unchanged across retries and restarts. The app calls the existing `applyWidgetActionV165` receipt transaction; no additional cloud subscription, collection design or standalone read is introduced.

After a successful transaction, the app applies its authoritative payload through the existing private-data coordinator and publishes a native snapshot containing a bounded `privateReceiptV196` proof. `privateAckV196` checks the current owner, command identity, revision and rebase flag against that proof. A pending successor for the same record can adopt the predecessor's new revision only after a fresh applied result. Replayed receipts never rebase onto a possibly newer edit from another device. A replay whose row was subsequently deleted may acknowledge with revision zero, removing the local overlay without recreating the deleted record.

Offline, transient and quota failures retain the frozen claim. A terminal validation or conflict failure moves the command to a separate owner-bound archive and rolls back optimistic routine or TODO completion. The widget keeps a visible synchronization status. Failed add drafts preserve their text and have explicit native recovery: reopen in the form with a new identity, or confirm deletion. Replacing an archived draft and saving the new command is one durable preference commit; a failed local write keeps the original draft. Active and failed add drafts together are limited to 100 so failure storage remains bounded without evicting text. Mutation failures retain the latest 20 record statuses and do not consume active queue slots.

The raw authenticated widget snapshot is never modified by these overlays. Daily completion totals and the seven-day graph derive from a copy with the owner's queued actions applied. Ordinary account changes invalidate gestures, queue reads, acknowledgement and recovery operations. The three bridge methods are `privatePendingV196(uid)`, `privateAckV196(uid, key, receiptJson)` and `privateFailV196(uid, key, errorCode)`.

## Verification and rebuilding

Use the signed v195 decoded source as the native baseline, then overlay the current widget Java/smali, native bridge methods, manifest and changed resources. The compiler must include the new helper, BroadcastReceiver, native note Activity and its generated lambda classes. Contracts are excluded from production DEX. Compile Java with Android35 and D8 at API26, rebuild with Apktool, then verify the original signing certificate, package/version, five providers, private component declarations and all bridge methods. Frozen app assets must match the final APK byte for byte.

`WidgetPrivateContractV196` covers coalescing, immutable claims, receipt checks, safe successor revisions, local TODO creation followed by completion before synchronization, week projection, terminal rollback, archive limits, account isolation, midnight gestures and completion undo. `WidgetNoteContractV196` and `test-widget-note-v196.cjs` cover the native form, routing and unchanged calendar geometry. `test-widget-core-v196.cjs` and `test-widget-routing-v196.cjs` retain the earlier model, privacy and command-routing coverage. Earlier routine, calendar and native model JVM contracts remain active against the new production classes.

Picker artwork is rendered from source XML and runtime text bindings, not an Android screenshot. Desktop compilation and these contracts do not prove launcher-specific inflation or behavior on a physical device.

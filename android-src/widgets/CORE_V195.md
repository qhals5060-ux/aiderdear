# One Routine widget in v195

Version code 195 / version name 1.9.85 preserves package `com.aiderlog.v22app` and the original signing certificate. The launcher registers CalendarMonth, CalendarCombined, CalendarSplit, CalendarFortnight and RoutineAll. The four calendar provider names are retained. RoutineCards and RoutineStats provider classes, manifest declarations, picker artwork and provider XML are retired. RoutineAll keeps its component name and existing preferences; its launcher label is **전체 루틴 · 주간 기록**.

Below the 24dp title, the available body has vertical weights **2:1**. The upper collection contains the existing scrolling routine list and MINI/MORE/MAX/SKIP controls. The lower panel is a **fixed seven-day aggregate chart**: every routine contributes to the daily counts, regardless of how many rows fit in the upper list. The heading shows the current week, practiced routines out of the total, and total practice-day occurrences. Each day has a fixed 12sp count and a horizontal progress bar, scaled against the total routine count. Future days show a dash. The lower panel never scrolls or shrinks its text as more routines are added. Tapping it opens the existing app Routine statistics tab (`data-r165-tab="statistics"`) after a UID check. Larger widgets also show the first two practiced routine names and the remaining count.

Practice is the union of legacy `doneDates` and dates with MINI/MORE/MAX in `dailyLevels`. An explicit SKIP overrides a legacy done date. Invalid or future dates do not count. Before both rendering and collection binding, native `atDay` rebases a copy of the snapshot to the actual local device date, recalculating today's level/count and the Monday–Sunday week. A widget refreshed Monday therefore stops showing Sunday's selected level and previous-week totals even if the app has not reopened. The source snapshot is unchanged. App step routines need no separate widget store: completing a run updates these same fields. `steps` and `stepHistory` are excluded from the widget projection; no new subscription, Firebase collection or remote query is added for routine widgets.

Normal/default layouts show weekday, date, count and progress bar. The minimum 250dp height keeps all seven counts visible. A legacy 170dp instance uses weekday/count cells, moves the summary into the title row, and hides bars and optional names. Large system fonts use the same compact treatment when space is short. The body stays 2:1. The provider advertises a 220dp minimum resize width and 250dp minimum resize height. Static configuration previews add only complete daily rows; the installed upper list remains scrollable.

The daily native collection, fixed statistics and commands remain owner-bound. The widget shows a login/sync placeholder when no owner is verified. Old RoutineCards/Stats app PendingIntents and queued commands are normalized to RoutineAll, then pass the usual UID and command validation. Removed launcher provider instances are subject to the launcher's removal behavior; their widget IDs cannot automatically become a different Android provider. RoutineAll IDs and settings remain compatible.

## Build and verification

Use the verified v194 decoded APK as the baseline. Overlay the production Java/smali, manifest, metadata and widget resources. Remove retired RoutineCards/Stats classes and provider/picker resources, including their public resource declarations, while preserving all surviving resource IDs. Compile the production widget Java files with ECJ/Android35, then D8 at min API26. Keep contract test classes out of the APK. Rebuild using Apktool with `--no-crunch`, then sign using the original key (certificate SHA-256 `1e08a903aef9c3a721510b64ec764d01d3d094eb954161b62544ea8f187b5953`). Tools, signing keys and binaries stay outside Git. Final app assets come from the root-approved frozen app stage and must match the APK byte for byte.

`test-widget-core-v195.cjs` checks week boundaries, practiced identities, SKIP/future exclusion, step completion compatibility, and calendar memo/todo projection. An optional output path writes its fixture for `WidgetCoreContractV195.java`. The JVM contract checks provider retirement, owner isolation, Sunday-to-Monday clock rollover, year boundaries, exact 2:1 geometry and aggregation across 30 routines beyond the visible list. The retained `WidgetNativeContractTest` covers existing calendar behavior. `test-widget-routing-v195.cjs` checks legacy command redirection, statistics/notebook routing and owner changes. `test-widget-resources-v195.cjs` checks supported RemoteViews classes, exactly seven count/bar pairs, non-scrolling statistics and all five progress palettes.

Picker samples are derived from the shipped XML and actual RemoteViews text/color bindings. They are not Android screenshots. Desktop compilation and model/resource contracts do not prove launcher-specific inflation, gestures or resizing on a device.

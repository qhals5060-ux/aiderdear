# Routine v165 구현 범위

앱의 Routine 화면만 변경했다. 웹사이트, Event, Daylog, 시스템 테마 목록, 휠 위치·색상·제어 코드는 수정하지 않았다.

## 원본 기능 대응

| 기존 기능 | v165 표시와 저장 경로 |
| --- | --- |
| 루틴 목록 / 상세 | 실천 탭에 원래 순서로 모두 표시. `routineMetrics`, `routineCycle`, `routineDetailHTMLV111` 재사용 |
| MINI / MORE / MAX / SKIP | 기존 `setRoutine` / `applyRoutineLevel` 재사용. 선택한 버튼을 다시 누르면 기존 빈 단계 저장 경로로 해제 |
| 날짜별 기록 | 최근 표시와 상세 회차 스탬프에서 기존 `cycleRoutineDate` 호출. 미래 날짜 제한 유지 |
| 생성·수정 | 원본 `routineEditorHTMLV111` 폼과 `saveRoutineEditorV111` 보존. 이름·기간·4색·MINI/MORE/MAX 필드, 기본값, 제한 유지 |
| 상세·삭제·조건부 완료 공유 | 기존 상세, 삭제 확인, `shareRoutineCompletion` 접근 유지 |
| 큰 목표 3개 / 실행 목표 각 8개 | 만다라트 탭에 세 표 모두 표시. 배열 인덱스 그대로. 목표별 임시 초안을 분리하고 수동 저장 |
| 목표 저장 | 기존 `saveRoutineGoalsV111` / `saveRoutineMandalaV111`에 선택적 `data-goal-index`를 전달. 다른 목표와 초안은 덮어쓰지 않음 |
| 전체 통계 | 기존 마지막 통계 렌더러의 계산 부분을 `AiderLogRoutineStatisticsV125.snapshot`으로 추출. 원래 팝업과 새 통계 탭 모두 같은 계산을 호출 |
| 글자 크기·테마 | 기존 `--app-*` 색상과 `--app-font-multiplier` 재사용. `data-css-typography`로 중복 인라인 크기 고정 방지 |
| 로컬 저장·로그인·동기화 | 기존 private 저장소와 `savePrivate` 그대로 사용. 새로운 API, 계정 조건, 데이터 마이그레이션 없음 |

## 화면 구조

- 고정 제목과 실천·만다라트·통계 탭, 남은 공간의 단일 콘텐츠 스크롤.
- 실천 카드: 이름/상세 → 회차 일수와 실천 횟수 → 기존 최근 최대 7일 → 네 단계와 사용자별 실행 설명.
- 만다라트: 목표별 3×3 인라인 편집, 120자 목표·100자 실행 목표, 이름 바로가기, 목표별 수동 저장.
- 통계: 약 77px 요약 → 현재 회차별 비교 → 최근 14일 → 전체 단계 분포와 요일. 무기록 막대는 높이 0.
- 루틴 편집: 가시 뷰포트의 60%, 고정 머리글/버튼과 가운데 입력 스크롤. 상세에는 60%를 강제하지 않음.

## 계산 경계

- 전체 실천/완료율: 기존 최근 30일.
- 전체 회차 최장: 루틴별 현재 회차 최장 중 최댓값.
- 개별 비교: 기존 현재 회차 실천·최장연속·완료율.
- 하루 흐름: 기존 최근 14일의 실천 루틴 수.
- 단계·요일: 기존 전체 `dailyLevels` 기록.
- 완료율 분모, 반올림, SKIP, 회차 경계, 누적 `doneDates` 처리는 변경하지 않음.

## 검증

격리된 비로그인 Chromium/WebView 미리보기에서 360×800, 390×844, 412×915, 720×844, 1100×800, 844×390을 확인했다. 실제 사용자 기록은 사용하지 않았다.

확인 항목: 생성·수정·취소·삭제·재실행, 네 단계 선택/해제, 미래 날짜 제한, 세 만다라트 표/24칸, 목표별 저장·다른 초안 보존, 긴 글자와 테마/글자 크기 변경, 시트 60%/가로 넘침, 휠의 변경 전후 좌표 동일.

기존 v164 계산 코드와 빈 기록·모두 SKIP·7/30/66일 회차 경계·8개 루틴 사례의 통계 수치가 일치한다. 6개 앱 팔레트의 주요 텍스트/컨트롤 대비는 4.5:1 이상이다.

실제 삼성 Galaxy Fold/Flip 하드웨어, 기기 키보드, 실제 계정의 서버 동기화·상대 공유 전송은 이 하위 작업에서 직접 실행하지 않았다. 네이티브 APK 설치 검증은 전체 릴리스 단계에서 별도로 수행한다.

기존 첫 실행 튜토리얼은 낮은 가로 화면에서 닫기 버튼이 화면 밖에 있을 수 있어, 루틴 가로 화면 검증은 세로 화면에서 튜토리얼을 닫은 후 회전했다. 튜토리얼 코드는 본 변경 범위에 포함하지 않았다.
